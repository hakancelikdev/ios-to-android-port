# ios-to-android-port

**An autonomous [Claude Code](https://claude.com/claude-code) loop that ports a Swift/SwiftUI iOS app to Kotlin/Jetpack Compose — feature by feature, with the iOS app as the specification.**

It is the exact system used to build the Android versions of two shipping apps:

| App | Ledger rows | Parity |
|---|---|---|
| **Vakit** — prayer times (App Store → Google Play) | 3,231 | 100 % code parity, visual parity loop running |
| **Meld** — tile-merge puzzle | 109 | 98 % (remaining rows owner-gated: store accounts) |

Porting Vakit's system to Meld changed only paths — the ledger checker is byte-for-byte identical. This repo is that system with the paths moved into one config file.

---

## How it works

```
                ┌───────────────────────── /loop /ios-port ─────────────────────────┐
                │                                                                  │
  parity_check.sh ─► resume? ─► pick next todo ─► read iOS ─► build on Android ─► gate ─► 2nd-agent review ─► commit + push ─► ledger
        ▲              │           (ledger)       (ios_cite)   (values, not intent)  │         │                                │
        │              └─ clean half-done work                                     red ─► revert ─► blocked ──────────────────┤
        └────────────────────────────────────────────────────────────────────────────────────────────────────────────────────┘
                queue empty ─► ios_sync_scan.sh (new iOS commits?) ─► experience-gap scan ─► parity report, loop stops
```

**1. The rule — "iOS is the spec."** `.claude/rules/ios-parity.md` says Android reproduces the iOS experience: layout, spacing (pt → dp 1:1), colors (same hex), copy, defaults, states, gestures, animation timing, haptics, analytics event names, domain logic (same input → same output). Differences are allowed only from a closed list (system-mandated, no iOS twin, unavailable tech like Liquid Glass/SF Pro, store policy, accessibility floor, and exceptions the owner wrote down). "Material convention" or "Android users expect…" is not a reason. The agent never asks "native or iOS-like?" — the answer is always iOS.

**2. The ledger — single source of truth.** `docs/port/parity-ledger.md` is a markdown table, one row per feature:

```
| ID | Feature / Screen | iOS source | Android target | Status | Commit | Note |
```

Status is `todo · doing · done · blocked · n/a`, with **at most one `doing`**. Nobody counts by hand: `tools/port/parity_check.sh` derives everything from the table and prints machine-readable lines (`STATUS`, `NEXT_TODO`, `PARITY_PCT`, `BLOCKED`). That is what makes every invocation resumable — after a usage limit, a crash, or a closed laptop, the next run reads the table and picks up exactly where the last one stopped.

**3. One invocation = one task.** The skill (`.claude/skills/ios-port/SKILL.md`) runs one task per call:

0. **Resume check** — leftover `doing`? finish it or revert it. The branch is always green.
1. **Bootstrap** (first run only) — inventory the iOS app and the Android repo, write the ledger in dependency order, commit, stop.
2. **Pick** the first `todo` → `doing`.
3. **Read iOS** — View + ViewModel + Domain + tokens. Citations are generated by `ios_cite.sh`, never written by hand (hand-written citations were the #1 recurring error: wrong directory, reading stopped two lines early, right file but wrong component, line drift).
4. **Build** the iOS experience on Android — port the values, restyle Material until it looks like iOS, custom components where it can't.
5. **Definition of Done** — parity, iOS-pinned tests for domain logic, same analytics, every language, tokens, changelog, app launched once.
6. **Quality gate** — your formatter, then your gate command (build, tests, lint, audits) + the ledger check. Red → no commit.
6.5 **Second-agent review** — a fresh-context `parity-reviewer` agent reads the staged diff against the iOS source. Narrow prompts only (broad ones hit the turn limit before the report is written).
7. **Commit + push**, then a separate ledger commit (`done` + SHA). Or: revert, mark `blocked` with a reason, move on.

Ceilings keep it from grinding: ~6 build/fix iterations per task, one screen/component per commit, stop after 3 `blocked` in a row.

**4. When the queue runs dry.** `ios_sync_scan.sh` lists iOS commits since the last synced marker in your user-facing directories and turns them into new rows; `ios_stale_strings.py` finds copy that changed on iOS after it was copied. Then an **experience-gap scan** compares one area per round side by side (same feature, different feel). Only when all three are empty does the loop stop itself.

**5. Visual parity (optional).** `ios-visual-parity` drives the running Android app with semantic selectors (`android_nav.sh`), screenshots it, and compares it against a gallery of iOS reference screenshots (`ios_ref_capture.sh`, via simulator + idb) — one screen per invocation, same ledger/gate/review/commit discipline.


## Requirements

- Claude Code, git, bash, awk, python3 (macOS or Linux).
- Your **iOS source checkout** next to the Android repo (any relative path). It is only read — the loop never commits, pulls or switches branches in it.
- An Android project with a real quality gate. **The loop is only as good as your gate** — build + unit tests + lint/detekt at minimum; architecture and token audits make it much better.
- Visual parity only: Android emulator + adb, Xcode simulator + [idb](https://fbidb.io).

## Install

```bash
git clone https://github.com/hakancelikdev/ios-to-android-port
./ios-to-android-port/install.sh ../MyApp-Android --ios ../MyApp-iOS
```

Existing files are never overwritten (`--force` updates skills/scripts; your ledgers under `docs/port/` are never touched). Then edit `tools/port/port.env`:

```bash
IOS_REPO="../MyApp-iOS"         # relative to the Android repo
IOS_BRANCH="main"               # loop stops if the iOS checkout is on another branch
IOS_SRC="MyApp"                 # Swift source root
IOS_SYNC_PATHS="MyApp MyAppWidgets"
LANGS="en:values tr:values-tr de:values-de"
ANDROID_PKG="com.example.myapp.debug"
ANDROID_ACTIVITY="com.example.myapp.MainActivity"
GATE_CMD="./gradlew :app:assembleDebug :app:testDebugUnitTest :app:lintDebug :app:detekt"
FORMAT_CMD="./gradlew :app:detektFormat"
PUSH_BRANCH="main"              # or "port/autopilot" to review through PRs
```

Check it: `bash tools/port/ios_ref.sh && bash tools/port/parity_check.sh` (should print `STATUS: BOOTSTRAP`).

Add this to the Android repo's `CLAUDE.md`:

```markdown
## The iOS app is the specification
Android reproduces the iOS experience as closely as the platform allows. **Read `.claude/rules/ios-parity.md`
before any UI or behavior work.** Port work runs through the ledger-driven loop `ios-port` (`/loop /ios-port`)
→ `docs/port/parity-ledger.md`. Config: `tools/port/port.env`. Every ported type carries a KDoc line
`iOS \`<SwiftName>\` counterpart`.
```

And let the loop run unattended — in `.claude/settings.json`:

```json
{
  "permissions": {
    "allow": [
      "Bash(bash tools/port/*)", "Bash(python3 tools/port/*)", "Bash(./gradlew*)",
      "Bash(git status*)", "Bash(git diff*)", "Bash(git log*)", "Bash(git show*)",
      "Bash(git add*)", "Bash(git commit*)", "Bash(git push*)", "Bash(adb*)"
    ]
  }
}
```

## Use

| You type | What happens |
|---|---|
| `/ios-port` | first time: builds the ledger from your iOS app and commits it. **Review it before looping.** Afterwards: does the next task. |
| `/loop /ios-port` | autonomous: one task per iteration until the queue, iOS sync and gap scan are all empty. Survives usage limits. |
| `/ios-port the settings screen` | directed: the request picks the task (finds it on iOS, binds it to a ledger row), does it, reports, stops. |
| `/loop /ios-visual-parity` | screen-by-screen screenshot comparison against the iOS gallery. |
| `/schedule` a nightly routine | proactive: scan new iOS commits, port the clean ones, mark owner-gated ones `blocked`. |

You stay the owner: rows that need you (store accounts, keys, product IDs, design decisions) go to `blocked` with a reason and are listed in `docs/port/owner-action-items.md`. Write your own design exceptions into `ios-parity.md` → "Owner-decided exceptions" and the loop will stop reopening them.

## Before you start the loop

- **It pushes.** By default every finished task is committed and pushed to `main` — that's the original workflow, and it works because nothing is committed before the gate passes. If you'd rather review, set `PUSH_BRANCH` to a work branch.
- **It spends tokens.** `/loop` keeps going until the queue is empty. A big app is hundreds of tasks.
- **Bootstrap is the judgement-heavy step.** Read the generated ledger, fix the order, split anything too large, move iOS-only things to `n/a`. A good ledger is most of the outcome.
- **It does not copy apps you don't own.** It reads your own iOS source; that's the whole premise.

## Lessons baked in

Every rule in the skill exists because something went wrong without it: hand-written citations, two `doing` rows, `git add -A` racing a parallel session, `git stash pop` writing conflict markers, unquoted heredocs eating backticks, "gate green" while the app crashed on launch, searching Android by iOS file name and declaring things missing, reviewers dying at their turn limit on broad prompts. They are listed under "Common mistakes" and "Red flags" in `SKILL.md` — read them once, they're short.
